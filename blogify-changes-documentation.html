4. Image Handling

Updated Placeholder Image URLs

The original placeholder image service (via.placeholder.com) was causing ERR_NAME_NOT_RESOLVED errors. We replaced it with a more reliable service (placehold.co) and improved the error handling for images throughout the application.

File: api/controllers/postController.js - createPost function

Updated the default placeholder image URL in the createPost function.

Before:

  jwt.verify(token, secret, {}, async (err, info) => {
    if (err) return next(err);
    try {
      const { title, summary, content } = req.body;
      const postDoc = await Post.create({
        title,
        summary,
        content,
        cover: req.file
          ? req.file.location // S3 file URL
          : "https://via.placeholder.com/400x200?text=Image+Not+Available",
        author: info.id,
      });
      res.json(postDoc);
    } catch (e) {
      next(e);
    }
  });

After:

  jwt.verify(token, secret, {}, async (err, info) => {
    if (err) return next(err);
    try {
      const { title, summary, content } = req.body;
      // Determine the cover URL based on storage type
      let coverUrl = "https://placehold.co/400x200/lightgray/darkgray?text=No+Image";

      if (req.file) {
        if (hasValidAwsCredentials && req.file.location) {
          // For S3 storage
          coverUrl = req.file.location;
          console.log("Using S3 image URL:", coverUrl);
        } else if (req.file.path) {
          // For local storage
          const relativePath = req.file.path.split('uploads/')[1] || req.file.filename;
          coverUrl = `/api/uploads/${relativePath}`;
          console.log("Using local image URL:", coverUrl);
        }
      }

      const postDoc = await Post.create({
        title,
        summary,
        content,
        cover: coverUrl,
        author: info.id,
      });
      res.json(postDoc);
    } catch (e) {
      next(e);
    }
  });

6. Summary

The modifications made to the Blogify application have significantly improved its reliability, flexibility, and user experience. Key improvements include:

  1. Proper Database Configuration: Ensured the application connects to the correct MongoDB database.
  2. Optional AWS S3 Integration: Made AWS S3 features optional, allowing the application to function properly without AWS credentials.
  3. Optional Google Authentication: Made Google authentication features optional, preventing errors when Google credentials aren't configured.
  4. Reliable Image Handling: Improved image handling with better placeholder images and error handling.
  5. Enhanced Error Handling: Added comprehensive error handling throughout the application to prevent crashes and provide better user feedback.

These changes ensure that the Blogify application can run smoothly in various environments, with or without external services like AWS S3 and Google Authentication.
